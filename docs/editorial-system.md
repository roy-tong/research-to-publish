# 从研究积累到可持续传播

一个品牌、一个研究底座、三个内容阵地。本文规定内容生产决策，具体账号排期与增长目标留在作者的私有工作台。

## 先写读者问题，再选渠道

研究按长期问题积累，内容按一次读者需求组织。一个研究可以产生多篇内容；一个内容也可以引用多个研究来源。先问这次新增了什么，再决定写在哪里。

| 本次变化 | 默认处理 |
| --- | --- |
| 已有事实变更、发现反例 | 先修订来源和判断，再查看受影响的已发内容 |
| 出现一个可独立解释的具体问题 | 做一篇社媒稿；不强制补齐其他渠道 |
| 出现有证据、边界和替代解释的新判断 | 网站保存完整论证，再评估公众号价值 |
| 只有新的包装、没有新的读者收益 | 复用既有内容或暂缓，避免重复发布 |
| 只有未证实的想法 | 留在私有研究中；不生成确定性结论 |

默认仍兼容旧专题的三个渠道。新专题可用 `topic --channels site` 等明确选择；既有专题用 `route`。研究资产始终保存在私有 workspace，未选 site 不表示允许忽略研究。

## 每篇内容的编辑 Brief

在专题目录保存 `content-brief.md`，由作者或 agent 撰写，不是 CLI 自动评估的事实。包含：

- 长期研究问题与本篇读者问题；两者可以不同。
- 具体读者、发生问题的场景、读完以后能改变什么判断或行动。
- 文章的一句话结论、支持它的 claim ID、最强反例与适用边界。
- 新增信息：新证据、新解释、新验证方法，或把旧资料用于一个新的读者问题。
- 传播理由：读者为什么点开、收藏或转发；继续关注作者还能获得什么。
- 渠道选择与跳过原因；对应既有网站文章时，注明是更新还是新发。
- 表达方案：案例、图解、演示、对照或文字论证；素材来源和缺口。
- 完成成本与停止条件；这次希望检验的一个问题。

这些问题用于编辑判断，不用加权打分伪装确定性。点击吸引力不能补偿证据缺失。

## 分别写作

网站保留完整依据、版本和可引用结论。公众号围绕专业读者需要判断的具体决策展开，给出替代解释与边界；不安排商业转化。小红书先把一个具体问题讲清楚，允许更轻的论证，但不能删掉会改变结论的限定条件。

同一研究的不同笔记应有不同的读者问题。更换标题、开头和封面，不足以形成新的内容价值。对于示范、体验、实测题材，只能使用实际完成的实验；外部评测必须说明来源。

## 反馈分三路

| 类型 | 下一步 | 是否影响已批准稿件 |
| --- | --- | --- |
| question | 检查原研究是否已经回答；决定补充解释或新建研究 | 不自动否定原判断 |
| expression | 修改标题、图解或叙事；改变稿件后重审 | 稿件改变会使审核失效 |
| counterevidence | 核对原始依据、定位 claim，检查其他复用内容 | 打开即阻止该专题审核和导出 |

分类由编辑负责。反对意见不自动等于反证，点赞也不是事实验证。记录来源、原话或准确摘要、具体下一步。反馈默认私有，不复制读者身份或后台数据到公开包。

`impact --source ID` 找出共享来源的专题、段落与发布回执。反证门禁只作用于反馈指定的专题；对其他共享来源专题需编辑逐一检查并记录，不能宣称自动完成语义传播。

## 成熟度按完成能力衡量

当前具备：来源快照、引用检查、渠道选择、构建审核、发布回执、人工导入反馈、依赖查询。

当前不具备：跨专题统一 claim 主库、单专题多篇同渠道 Publication 对象、后台数据自动采集、统计归因、无人值守发布。多篇内容现在用不同 topic ID 共享来源；claim 属于各专题，尚不能跨专题一次修改全部同步。

下一阶段先用两个真实研究专题检验流程，再决定是否抽出全局 Claim 与 Publication。抽象的验收标准是：同一判断的两篇内容能追踪到同一修订版本，旧回执保持可查，旧 workspace 可迁移并回滚。不能只新增几个目录就称为完成知识资产复用。
